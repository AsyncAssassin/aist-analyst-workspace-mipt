# Проверяемые сценарии

Каталог описывает ожидаемые свойства приложения. Идентификаторы A01-A18 связывают сценарии с [примерами HTTP-запросов](examples/http-chain.json). Наличие строки или корректного JSON-примера не означает, что соответствующий интеграционный тест был выполнен.

Проверки доступа и конкуренции используют синтетических пользователей и отдельную БД. Инструкции запуска и условия отдельных наборов находятся в `docs/testing.md` от корня репозитория.

| ID | Ожидаемое поведение |
| --- | --- |
| A01 | Чужие project/source/version/run/export через API и инструмент дают одинаковый 404. Нет содержимого, current_revision, нового Message/Run/ToolCall, cache hit чужой области или model POST. Проверить подмену каждой связи и отзыв прав после запуска |
| A02 | Upload вычисляет SHA по bytes и создает Source/Version один раз. Повтор того же key+metadata+bytes возвращает те же ID; другие bytes с тем же key дают 409. Ready имеет реальное число страниц, текст/основания именно этого PDF. Новый processor/version не изменяет прежний source pin. Неподдерживаемый PDF не вызывает LLM |
| A03 | Два конкурентных одинаковых POST дают один Run и Message. Повтор после потери HTTP-ответа и перезапуска возвращает тот же ID без provider POST. Тот же key с иным нормализованным содержанием дает 409. Lookup receipt предшествует CAS: успешный edit-repeat со старой revision не создает вторую версию |
| A04 | Cancel и save конкурируют за одну блокировку. Если cancel выиграл, result=null, ArtifactVersion/assistant-success не появляются, поздний ответ сохраняет только call/usage/events. Если save выиграл, cancel дает run_terminal. Повтор failed/cancelled никогда не возобновляет агентный цикл. Проверить отмену ровно своего executor run/session |
| A05 | Реальная ошибка read_source с тем же executor_tool_call_id записывается как ToolFailure. Failed Run содержит код и безопасное объяснение, а не успешные финансовые claims. Изменение языка сообщения не меняет классификацию; regex error_answer отсутствует |
| A06 | Обрыв SSE не меняет Run. Reconnect после seq=N дает только seq>N, включая поздний usage terminal Run. Дубликаты доставки удаляются по run/seq. Несогласованный Last-Event-ID, чужой run и будущая seq дают cursor_invalid. Журнал и snapshot изменяются атомарно |
| A07 | Сумма расходов включает agent, extraction, semantic_check и другие включенные модельные операции. Две конкурентные отправки не превышают свободный резерв. Reasoning не прибавляется к output. Estimate и per-call billed замещают друг друга; supersedes не удваивает расход. Часовой partial aggregate не разносится на calls и не складывается второй раз |
| A08 | Разрыв до/после отправки, timeout, потеря DB commit acknowledgement дают различимые attempted/sent/observed/unknown. Неизвестные tokens/cost/billed остаются null с причиной, резерв удержан. Перезапуск не делает второй provider POST. Recovery сверяет сохраненные pins, не берет latest source |
| A09 | Две правки expected_revision=1 дают одну revision=2; вторая получает 409. Исторический parent можно выбрать при CAS текущей головы. Fact/Evidence/raw/период/SHA неизменны; 716 млн и 0.716 млрд нормализуются в одно значение. Старые версии доступны. Числовая подмена с прежним fact ref отклоняется |
| A10 | Acceptance версии 1 не появляется у версии 2/3. Принимается только указанный version ID/SHA, с CAS VersionReview, проверенными validation IDs и явным acknowledgement semantic not_checked. Модель не может вызвать accept. Проверки принятой версии не переписываются; принятие не меняет их статус |
| A11 | Короткий вопрос сохраняет evidence_answer и открываемое основание, без аналитической записки, renderer или Export. Вопрос о неизвестном факте возвращает missing_information в пределах реально просмотренного корпуса, без подмены прогнозом |
| A12 | DOCX/PDF собираются из одной выбранной ArtifactVersion. Все identity поля сохранены. Новый theme дает другой Export при том же content SHA. Одинаковый identity с двумя ключами дает один Export. Draft имеет видимое обозначение; accepted требует принятия этой версии. SHA файла подтвержден bytes и проверкой выпуска |
| A13 | Повтор GET file сохраняет SHA и нулевой прирост LLM/renderer calls. Missing дает 410, corrupt 409; повтор POST того же identity не пересобирает. Сбой commit: confirmed failed очищает только свой файл, completed/unknown сохраняют его. Ошибка cleanup видима. Чужие файлы и symlink не удаляются |
| A14 | Unknown/future result type, неподдерживаемый формат, несовместимый шаблон, отсутствующий инструмент или disabled профиль отклоняются до платного действия. Planned/future registry не становится enabled по наличию JSON-примера. Превышение настроенного числа источников отклоняется до модельного вызова |
| A15 | Удерживать собственный handler дольше polling и shutdown deadline; SIGTERM запрещает новые операции и не выходит преждевременно до выбранной границы ожидания. Ответ до deadline сохранен; после deadline call=unknown, резерв удержан, Run=recovery_required либо прежний terminal. Проверить согласованную последнюю запись, startup recovery, потерю DB и отсутствие второго POST. Успешный server_close daemon не является assertion ожидания |
| A16 | Продолжение использует именно сохраненную выбранную v2, дает v3 с parent=v2, другой аудиторией/разделами и acceptance=null. Числа, периоды, основания и ручной абзац сохраняются либо показываются в осмысленном diff. Если голова изменилась в процессе модели, save дает revision_conflict. Смена типа создает новый Artifact с derived_from_version_id |
| A17 | Истечение worker lease блокирует запоздалый save старого worker. Waiting prompt и reply durable, повтор input не добавляет Message дважды. В waiting нет активной платной работы. Recovery->running разрешен только при установленном исходе и сохраненном checkpoint, без самостоятельного второго agent loop |
| A18 | API сериализует ответы по схеме без дополнительных owner/path/secret/reasoning полей. getRun -> getVersionById использует project_id/result_version_id ответа. Message и result_saved ведут к той же сохраненной версии, включая историческую. Lookup проверяет owner/project и возвращает одинаковый 404 для чужих версий. Frontend использует контрактные примеры и обрабатывает ошибки по коду. Навигация редактора защищает несохраненные правки; возврат восстанавливает разговор и выбранные версии источников |

Схемы проверяют форму и локальные ограничения JSON. Соответствие основания хранилищу, доступ, конкуренция, восстановление, выпуск и отсутствие повторных расходов проверяются на работающей реализации. Результат такой проверки относится к выполненному набору и его условиям.
