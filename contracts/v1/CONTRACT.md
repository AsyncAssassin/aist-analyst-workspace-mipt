# Контракты AIST

Пакет определяет формат данных, HTTP API и инструменты, которыми пользуются интерфейс и исполнитель. Он применяется backend и frontend совместно. Перечень доступных операций конкретной среды дополнительно зависит от ее конфигурации и зарегистрированных возможностей.

JSON Schema является источником полей и ограничений. Описание HTTP API использует ссылки на те же определения. Это собственный проверяемый формат, а не документ OpenAPI. Внешние поля, отсутствующие в соответствующей схеме, отклоняются.

Примеры описывают вымышленный квартальный отчет «Спектромера». Два факта и точный расчет роста составлены для проверки денежных строк, периодов и связей с версией источника. SHA и размеры исходного PDF и выпуска иллюстрируют поля, файлы не поставляются. Отпечатки запросов, аргументов, содержимого версии и идентичности выпуска рассчитаны по JSON-примерам.

## Основные сущности

- `Project` и `Conversation` объединяют документы, сообщения и задачи пользователя.
- `Source` и `SourceVersion` описывают документ и точную версию его содержимого.
- `Fact` и `Evidence` связывают извлеченное значение с источником и адресом основания.
- `Run` хранит параметры и состояние выполнения. `ModelCall`, `ToolCall` и записи usage фиксируют обращения и учет.
- `Artifact` объединяет версии результата. `ArtifactVersion` содержит сохраненный результат, его основания и происхождение.
- `VersionReview` хранит проверку и принятие конкретной версии. `Export` описывает выпуск DOCX/PDF из этой версии.

Точные имена определений, поля и допустимые связи находятся в схеме. Синтетические JSON-примеры показывают форму данных и не являются журналом работы приложения или подтверждением качества записки.

## Доступ и повторные операции

Сервер определяет пользователя по своей сессии. Клиент и модель не назначают владельца передаваемым полем. Доступ проверяется для проекта и каждого связанного источника, задания, результата и файла. Чужой объект не раскрывается через служебные поля ошибки или сведения о текущей ревизии.

Изменяющие операции используют предусмотренные контрактом ключи идемпотентности и ожидаемые ревизии. Повтор подтвержденной операции с тем же содержимым возвращает сохраненный результат. Несовместимое содержимое или устаревшая ревизия приводят к соответствующей ошибке. Чтение исторической версии не подменяется чтением последней версии.

Коды HTTP, поля ошибок и условия повторения определены в `http.json` и схемах. Интерфейс обрабатывает код ошибки, а не текст сообщения на определенном языке.

`listSourceFacts` (GET списка фактов версии источника) и `listArtifacts` (GET списка артефактов проекта) описаны в контракте как проектные операции. В приложении эти маршруты не зарегистрированы. Чтение отдельного артефакта и его версий доступно по отдельным маршрутам.

Для `decideEdit` квитанция хранится в области владельца, проекта, операции и предложения. Повтор того же решения с тем же ключом возвращает сохраненное решение. Другое решение с тем же ключом дает `idempotency_conflict`. Для нового ключа противоположное решение уже обработанного предложения дает `revision_conflict`.

## Значения и основания

Денежные и другие точные десятичные значения передаются строками с отдельными полями единицы, масштаба и периода. Их нельзя превращать в двоичный floating point ради вычислений или оформления. Расчеты сохраняют исходные значения и правила округления.

Для нового исследования дата отсечения публикаций определяется днем создания Run по Europe/Moscow. Уже сохраненная дата исследования используется при продолжении. Дата шапки соответствует дню создания версии по Москве. Служебные временные метки хранят момент времени, а торговая дата MOEX берется из ответа биржи.

Основание относится к конкретной версии источника. Смена файла, страниц, факта или периода не должна незаметно менять сохраненный результат. Внешние сведения сохраняют ссылки на проверяемые элементы контекста. Неизвестное значение не заменяется нулем, прогнозом или данными другого периода.

## Выполнение и учет

Задача и события сохраняются сервером. Переподключение к потоку событий продолжает чтение с согласованной позиции; разрыв соединения интерфейса не создает новую задачу. Отмена, завершение и запоздалый ответ исполнителя обрабатываются относительно актуального состояния Run.

Модельные обращения проходят резервирование и общий учет. Неизвестный исход остается явно неопределенным и не разрешает самостоятельный повтор платной отправки. Наблюдаемый usage, оценка и полученные сведения о стоимости должны сохранять происхождение без двойного счета.

Удержание после HTTP-отказа снимается автоматически только по точному совпадению с правилом `UnbilledProviderRules` в закрепленной серверной политике Run. В `unbilled_errors` задаются версия и источник правила, provider, protocol, endpoint, профиль, финансовая область, версия тарифа, HTTP-статус и точные поля типизированной ошибки. Отсутствующее поле эквивалентно пустому списку. Некорректная конфигурация не разрешает освобождение. Полный подтвержденный отказ дает запись `reconciliation` с estimate 0 и прежним billed, если он известен. Внутреннее `PolicyRefusalEvidence` хранит ссылку на закрепленное правило и SHA точных файлов исполнения.

Окончательная индивидуальная сверка создает `provider_invoice` с известным billed, включая ноль. Внутреннее `OperatorBillingEvidence` содержит привязку к вызову и расчетной области, утверждение доверенного локального оператора по конкретной строке первичного основания и ожидаемый предшественник. Индивидуальная сверка неизвестного вызова меняет его финансовый exposure, сохраняя неизвестный транспорт и запрет повтора. Подтвержденный billed сохраняет приоритет после позднего ответа. BillingAggregate остается отдельным наблюдением без индивидуальной атрибуции.

Служебное основание хранится в неизменяемой записи ledger. Маршруты чтения возвращают прежнюю форму UsageEntry после проверки owner/project. Комплект отказа версии 2 публикуется атомарно. Комплекты успешных ответов версии 1 сохраняют поддержку.


## Внешнее чтение

Новый вызов `aist_web_fetch` разрешен для публичного HTTPS URL из конкретной завершенной успешной выдачи `search_id` того же Run. Для адреса из текста страницы, PDF или задания сначала нужен поиск с этим URL в выдаче. Приложение сравнивает канонические URL до учета сетевого запроса и повторного использования выдержки. Точный повтор сохраненной операции возвращает прежний результат. Чтение сохраненного текста через `aist_read_web` доступно без сети с действующими правами.

Приложение приводит имя домена к IDNA в нижнем регистре, убирает явный порт 443 и fragment, заменяет пустой путь на /. Путь и строка запроса, включая порядок параметров и percent-encoding, сравниваются дословно. Предел 2048 символов действует до и после нормализации. IP-литералы, userinfo, альтернативные порты и неоднозначные формы адреса отклоняются.

Выдержка Parallel принимается по совпадению возвращенного канонического URL с запрошенным. `response_sha256` относится к ответу MCP, `page_sha256` равен null. Сетевой маршрут поставщика до страницы находится за пределами проверки AIST.

## Сохранение, правки и выпуск

Ответ по источнику и аналитическая записка являются разными типами результата. Сохранение проверяет тип, структуру и основания через инструменты приложения. Редакторская правка создает дочернюю версию и не изменяет исходную.

Программная проверка, содержательная оценка и принятие человеком имеют разные состояния. Отсутствие выполненной содержательной проверки обозначается явно. Принятие закрепляется за точной версией и ее содержимым; модель не принимает записку от имени пользователя.

DOCX/PDF выпускаются из выбранной версии с определенными настройками шаблона и renderer. Повторное скачивание готового файла не запускает генерацию записки заново. Ошибка или отсутствие файла не разрешает подменить его выпуском другой версии.

Новые аналитические записки используют технический профиль `note-technical.v29`. Он проверяет права, происхождение, версии и SHA, а для финансовых строк проверяет значение, знак, масштаб, валюту, единицу, период и метрику по сохраненным основаниям. Свободная проза и заголовки не проходят грамматическую проверку чисел. Смысловая проверка сохраняет `not_checked`. Принятие конкретной версии требует явного подтверждения этого статуса человеком. Для `evidence_answer` действует строгая проверка числовых утверждений.

## Проверка пакета

```bash
python contracts/v1/validate.py --package-only --manifest
```

Валидатор проверяет схемы, примеры, локальные ссылки, ID сценариев, связи сущностей, точную арифметику примеров и контрольные суммы. Он не выполняет HTTP-сервер, PostgreSQL или модельный цикл. Команды установки зависимостей и интеграционных проверок приведены в `docs/testing.md` от корня репозитория.

`MANIFEST.sha256` фиксирует состав этого пакета, а корневой `SHA256SUMS` фиксирует распространяемый комплект. Контрольные суммы схем и ресурсов используются приложением и проверками целостности.

Для рабочего профиля OpenClaw `Registry.model_execution.state=temporarily_unavailable` означает, что API не видит свежий сигнал совместимого worker. Новый запрос сообщения или продолжения получает `temporarily_unavailable` (503) без новой квитанции. Точный повтор уже принятой операции по тому же ключу возвращает сохраненный результат; изменение тела по тому же ключу дает конфликт. Чтение истории, выпуск и скачивание продолжают использовать свои проверки.
