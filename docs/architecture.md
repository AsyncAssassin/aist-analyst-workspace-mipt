# Архитектура AIST

AIST объединяет работу с документами компании, диалог с аналитическим исполнителем и подготовку записок. Приложение хранит исходные материалы, основания выводов и историю изменений независимо от модельного провайдера.

## Компоненты

| Компонент | Ответственность | Исходники |
| --- | --- | --- |
| React и TypeScript | Проекты, чат, источники, редактор и скачивание | [apps/web/src](../apps/web/src) |
| Node web server | Раздача интерфейса и проксирование API | [server.mjs](../apps/web/server.mjs) |
| FastAPI | Авторизация, HTTP API, проверка доступа и прием задач | [main.py](../apps/backend/app/main.py), [api.py](../apps/backend/app/api.py), [auth.py](../apps/backend/app/auth.py) |
| Прикладной backend | Документы, факты, расчеты, версии, проверки и учет | [apps/backend/app](../apps/backend/app) |
| Worker | Выполнение задач и выпуск файлов | [worker.py](../apps/backend/app/worker.py) |
| PostgreSQL | Прикладное состояние, связи и журнал операций | [database.py](../apps/backend/app/database.py), [миграции](../infra/migrations/versions) |

API и worker используют одну Python-сборку и общую прикладную БД. Доступность поиска, новостей и внешних провайдеров определяется конфигурацией среды.

## Путь от документа до записки

1. Пользователь создает проект, загружает PDF и выбирает материалы в чате. Backend проверяет владельца и сохраняет точную версию источника.
2. Приложение разбирает текст и раскладку страниц. Для поддерживаемых задач модель извлекает факты из текста или изображений; сервер проверяет их форму и связь с источником.
3. Worker выполняет сохраненную задачу. Аналитик читает предоставленные материалы, получает факты и при необходимости вызывает исследование публичных источников.
4. Инструмент сохранения проверяет содержание, версии оснований и состояние задачи. Результат записывается как версия артефакта с историей и результатами проверок.
5. Редакторская правка создает новую версию. Для выбранной версии приложение выпускает DOCX/PDF; повторное скачивание возвращает сохраненный файл.

## Версии, основания и доступ

Источники и результаты связаны с конкретными версиями. Обновление документа или записки не переписывает прежние основания. Числовые значения сохраняют единицу, масштаб, период и происхождение; вычисления используют точные десятичные значения и дроби.

Проверки владельца и проекта выполняются сервером для HTTP и инструментов исполнителя. Модель не управляет правами, версиями, расчетами или учетом. Повторная отправка операции обрабатывается по ключу идемпотентности; изменение существующего состояния проверяет ожидаемую ревизию.

Сохранение черновика, программная проверка, принятие пользователем и выпуск файла являются отдельными действиями. Принятие относится к определенной версии и ее содержимому. Оно не наследуется новой версией. Технически корректная записка может требовать содержательной проверки человеком.

## Модельный провайдер и исследование

[Транспорт OpenAI](../apps/backend/app/openai_responses.py) и [общий транспорт](../apps/backend/app/transport.py) обслуживают профиль `model_openai-astra-xhigh-v1`: `gpt-6-astra`, reasoning `xhigh`, стандартный тариф. Flex в этом профиле не включен. Доступ к модели предоставляет API-проект оператора.

Аналитик и исследователь работают в отдельных сеансах OpenClaw. Аналитик видит задачу и выбранные документы; исследователь получает сформулированное задание и публичные материалы. Система не передает ему исходные документы и полный диалог автоматически. При этом само задание исследователю может содержать сведения из пользовательского запроса.

Исследователь читает сохраненные части материалов с адресами фрагментов. Закрытие сбора учитывает обязательные темы, владельцев и существенные суммы проектов. Сохранение полной записки требует серверной проверки оснований и явного `ownership_review`.

Кешируемый контекст отделен от изменяемых сведений об оставшемся бюджете. Ключ кеша изолирован по владельцу, проекту, задаче, сеансу исполнителя и версии тарифа. PDF-извлечение и прямое переписывание фрагмента не используют этот кеш. Попадание в кеш подтверждается данными usage.

### Исходящие запросы и сохраненные материалы

Backend вызывает внутренний News по `AIST_NEWS_ORIGIN`. GET `/web-search` получает аргументы инструмента, срок и идентификатор сессии. GET `/web-fetch` получает канонический URL, дату среза, срок, лимит байтов, objective и идентификатор сессии. Строка запроса относится к внутреннему маршруту News.

News вызывает Parallel на `https://search.parallel.ai/mcp` через POST JSON-RPC `tools/call`. У `web_search` в аргументах находятся `objective`, `search_queries` и `session_id`. У `web_fetch` передаются `urls` с одним URL, `full_content=false`, `allow_live_fetch=true`, `objective` из выбранного поиска и `session_id`. `session_id` вычисляется как SHA-256 канонического JSON с полем `public_research` и идентификатором Run. Он одинаков для всех таких запросов одного Run, включая уточнения, и служит для корреляции. Учетные данные пользователя и ключ модели не входят в этот запрос.

Модель формулирует исследовательское задание и поисковые запросы. Инструкции требуют публичных сведений. В сформулированные моделью `objective` и `search_queries` может попасть закрытый текст, в том числе под действием инструкций из источника. Контроль URL ограничивает выбор адреса. Он не определяет, содержит ли поисковый запрос закрытые сведения, и не гарантирует защиту от инструкций внутри источника.

AIST допускает новое чтение только по URL из конкретной сохраненной успешной выдачи своего Run. Для ссылки из страницы или документа нужен поиск с этим адресом в выдаче. AIST проверяет совпадение канонического адреса записи Parallel с разрешенным URL. Извлечение страницы, DNS, TLS и переходы до нее выполняет Parallel. AIST получает выдержку и хеш ответа MCP, полный оригинал и его хеш не сохраняются. Точный повтор сохраненной операции и чтение фрагмента по `evidence_id` используют локальные данные. Для старого маршрута `/news` отдельный HTTPS-reader сам проверяет все DNS-адреса и сертификат. Этот маршрут ограничен разрешенными издателями и отключает редиректы. Сам reader при разрешенных переходах ограничивает их исходным HTTPS origin и общим сроком.

В PostgreSQL хранятся результаты поиска с аргументами и сниппетами в `aist.tool_calls`, состояние запросов с каноническим URL, objective и хешем аргументов в `aist.web_requests`, выдержки, атрибуция, даты, хеш ответа MCP и счетчики в `aist.runs.external_context`. Использованные основания сохраняются в снимке версии записки. Тела запросов и ответов Parallel целиком в эти записи не копируются.

Каталог исполнения содержит `<run_id>/tools.jsonl` и `<research_id>/tools.jsonl` с аргументами и результатами инструментов, каталоги `calls/` с файлами модельных запросов `*-request.json` и ответов `*-response.json` или `*-response.sse`, сеансы OpenClaw в `<run_id>/state/agents/*/sessions/` и технические журналы. Продолжения Run используют подкаталог `continuation-<turn>`. Файлы и записи могут содержать данные проекта в открытом виде на прикладном уровне. Файлы доступны worker, другим процессам с подключенным хранилищем и нужными файловыми правами, а также оператору хоста или хранилища. Приложение предоставляет пользователю данные проекта по правилам владельца и проекта. Прямой доступ к таблицам имеет роль подключения приложения и оператор БД.

Скрытие чата меняет его видимость. Оно не удаляет автоматически источники, версии, расходы, журналы и файлы исполнения.

В локальном профиле комиссии `infra/compose.local.yaml` worker и backend монтируют том `<имя проекта Compose>_execution` в `/data/execution`. PostgreSQL использует том `<имя проекта Compose>_database`. Имя проекта по умолчанию `aist-local`. Технические проверки создают отдельное временное окружение.

## Выполнение и учет

Приложение сохраняет задачу до запуска исполнителя, контролирует срок владения задачей worker и отклоняет запоздалое сохранение от утратившего владение процесса. Отмена и сохранение согласованы с текущим состоянием задачи. Отключение интерфейса от потока событий не отменяет выполнение.

Расход резервируется до обращения к провайдеру. Наблюдаемый ответ и usage проходят через общий учет, включая вложенные исследования и извлечения. Неизвестный исход удерживает резерв; потеря соединения не разрешает автоматическую повторную платную отправку.
